# 의사결정 기록

## 기록 원칙

중요한 결정은 날짜, 이유, 대안, 영향범위, 후속조치를 남긴다. 단순 결과만 기록하지 않고 왜 그렇게 결정했는지를 보존한다.

---

## 2026-08-04 — AIPOS 문서체계 채택

### 결정

LAYAD 문서를 단순 개발자료가 아니라 AI 프로젝트 운영 표준과 컨설팅 자산으로 관리한다.

### 이유

- 대화 중 결정이 파편화됨
- 사업자료와 기술자료가 혼합됨
- 설계와 구현 상태가 반복적으로 혼동됨
- 향후 다른 기업 프로젝트에 재사용할 필요가 있음

### 영향

- 한글 표준 문서세트 구성
- GitHub를 프로젝트 지식저장소로 활용
- 요구사항 상태와 의사결정 이력 관리

## 2026-08-04 — 2트랙 운영 채택

### 결정

운영 MVP와 설계·차기 기능을 분리한다.

### 이유

문서 정리와 신규 기능 개발이 현재 MVP 안정성을 훼손하지 않도록 하기 위함이다.

### 적용

- 트랙 A: 운영 안정화와 긴급 오류 수정
- 트랙 B: 문서, 설계, 실험, 차기 기능

## 2026-08-04 — 상품 적합도를 서비스 중심가치로 확정

### 기존

16유형 테스트와 상품 신청 기능 중심

### 변경

사용자의 Beauty Code와 선택 상품이 얼마나 잘 맞는지를 핵심 가치로 정의

### 영향

- 사용자 결과 우선순위 변경
- 관리자 최근 신청에 점수·등급·순위 표시
- 상품별 16유형 점수표와 히트맵 필요
- KPI를 적합도 등급 중심으로 보완

## 2026-08-04 — MVP에서 OpenAI API 제외

### 결정

MVP 자동분석에 OpenAI API를 사용하지 않고 운영자가 ChatGPT Plus 등으로 분석한 결과를 입력한다.

### 이유

- 오너에게 별도 API 비용이 사전 설명되지 않음
- MVP 단계의 비용과 운영복잡도 최소화
- 분석 기준과 사용자 반응을 먼저 검증

### 후속과제

- 운영자 입력화면
- 분석 근거와 버전 기록
- 자동화 전 비용·품질·책임 검토
