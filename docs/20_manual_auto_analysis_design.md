# LAYAD 상품 적합도 분석 모드 설계

## 목적
오너 검증 단계에서는 OpenAI API 비용 없이 수동 분석 모드를 운영하고, 검증이 끝난 뒤 동일한 승인 구조를 유지한 채 자동 분석 모드로 전환한다.

## 공통 운영 원칙
- 승인 단위는 1건이다.
- 운영자는 AI가 생성한 16유형 점수를 수정하지 않는다.
- 결과가 적절하지 않으면 다시 분석하거나 보류한다.
- 승인된 결과만 사용자에게 공개한다.
- 규칙 기반 Beauty Code 16유형 판정은 AI로 표현하지 않는다.

## 수동 분석 모드 — 오너 검증 기본값

### 운영 절차
1. 운영자가 상품 분석 요청을 선택한다.
2. `지시문 복사`를 누른다.
3. ChatGPT에 지시문을 붙여넣어 실행한다.
4. ChatGPT가 반환한 JSON 전체를 복사한다.
5. 관리자 화면의 결과 입력란에 JSON을 붙여넣는다.
6. `결과 검증`을 누른다.
7. 앱이 16개 코드, 점수 범위, JSON 형식을 자동 검증한다.
8. 운영자는 읽기 전용 결과를 확인하고 `승인 및 공개`, `다시 분석`, `보류` 중 하나를 선택한다.

### 비용
- 앱의 OpenAI API 사용 비용은 0원이다.
- 운영자의 ChatGPT 구독 비용은 앱 비용과 별도다.

### UI 원칙
- 16개 점수를 개별 입력하거나 수정하는 입력창은 제공하지 않는다.
- JSON 전체 붙여넣기 방식만 사용한다.
- 검증 완료 전에는 승인 버튼을 제공하지 않는다.
- 수동 모드가 현재 운영 방식임을 명확하게 표시한다.

## 자동 분석 모드 — 오너 검증 후 전환

### 예정 절차
1. 앱이 OpenAI API로 상품을 분석한다.
2. 16유형 점수와 요약을 자동 생성한다.
3. 앱이 결과 형식을 자동 검증한다.
4. 승인 대기 1건을 운영자에게 알린다.
5. 운영자는 `승인 및 공개`, `AI 재분석`, `보류` 중 하나를 선택한다.

### 비용 통제 예정 항목
- 일일 및 월간 예산 한도
- 일일 분석 건수 한도
- 동일 상품의 기존 결과 재사용
- 상품별 재분석 횟수 제한
- 모델별 예상 단가 표시
- 예산 한도 도달 시 자동 분석 중지

## 분석 상태

### 수동
`submitted → analyzing → manual_result_validated → completed`

예외 상태:
`manual_parse_failed`, `held`

### 자동
`submitted → ai_analyzing → approval_pending → completed`

예외 상태:
`ai_failed`, `validation_failed`, `reanalysis_requested`, `held`

## 오너 인수 기준
1. 수동 모드가 기본 선택으로 표시된다.
2. 자동 모드는 오너 검증 후 기능으로 구분된다.
3. 상품별 분석 지시문을 한 번에 복사할 수 있다.
4. ChatGPT JSON 결과를 한 번에 붙여넣을 수 있다.
5. 16개 코드가 누락되거나 점수가 0~100 정수가 아니면 검증이 실패한다.
6. 검증된 결과는 읽기 전용으로 표시된다.
7. 운영자는 점수를 수정할 수 없다.
8. 승인 시 기존 상품 ID를 재사용하고 결과를 공개한다.
9. 다시 분석 시 이전 입력을 초기화하고 새 결과를 받는다.
10. 보류 시 결과를 공개하지 않는다.
11. main 브랜치와 Vercel 운영 환경에는 검토 전 반영하지 않는다.
