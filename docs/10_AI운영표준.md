# AI 운영 표준

## 1. 목적

AI 도구별 역할과 비용·보안·품질 책임을 구분하여, 같은 오류를 반복하거나 대화에만 의존하는 개발을 방지한다.

## 2. 역할 구분

### ChatGPT

- 사업목표와 사용자 문제 정리
- 요구사항 통합
- 제품·UX 설계
- 문서 작성과 충돌 검토
- 테스트 시나리오와 운영 가이드

### Codex

- 승인된 기술설계 기반 코드 작성
- 작은 단위 수정
- 테스트와 리팩터링
- 변경 파일과 검증 결과 보고

### GitHub

- 승인된 설계와 기술자료의 기준 저장소
- 코드와 변경이력 관리
- 브랜치와 커밋을 통한 상태 구분

### Supabase

- 운영 데이터와 스키마 관리
- 권한·정책·마이그레이션 관리

### Vercel

- 미리보기와 운영 배포
- 환경변수와 빌드 상태 관리

## 3. 작업 시작 규칙

AI는 작업 전에 다음을 확인한다.

1. 프로젝트 헌장
2. 현재 MVP 현황
3. 목표 설계
4. 요구사항 상태
5. 관련 의사결정 기록
6. 데이터·배포 영향

충돌하거나 불명확하면 임의 구현하지 않고 확인을 요청한다.

## 4. 명령 구분

- `설계만`: 문서와 설계안만 작성, 코드·DB·배포 금지
- `개발`: 코드 반영, 운영 배포 금지
- `개발 및 배포`: 코드 반영과 승인된 운영 배포
- `검증`: 현재 상태를 읽고 테스트하며 임의 변경 금지

## 5. 비용 관리

- ChatGPT Plus와 OpenAI API 과금은 별개임을 고객에게 설명한다.
- 유료 API 도입 전 월 예상량·단가·상한·중단조건을 정의한다.
- MVP에서는 수동 운영이 더 경제적이면 자동화를 보류한다.
- AI 사용량을 줄이기 위해 오류 반복보다 원인분석을 우선한다.

## 6. 보안과 개인정보

- 비밀키를 대화, 코드, 문서, 화면에 노출하지 않는다.
- 고객 데이터와 개인정보를 공개 AI 입력에 넣기 전 정책을 확인한다.
- 수집 목적이 불명확한 정보는 저장하지 않는다.
- AI 생성 결과는 검수 없이 운영 의사결정으로 확정하지 않는다.

## 7. 품질 책임

- AI가 작성한 코드와 문서는 사람이 승인한다.
- AI가 성공했다고 말한 것만으로 완료로 인정하지 않는다.
- 커밋, 빌드, 운영주소, DB 결과를 근거로 검증한다.
- 오류 발생 시 같은 수정 반복을 중단하고 현재 상태와 원인을 다시 확인한다.

## 8. 프롬프트·에이전트 관리

- 공통 규칙은 `AGENTS.md`에 둔다.
- 특정 업무 절차는 역할별 지침 또는 Skill로 분리한다.
- 프롬프트에는 목표, 입력, 금지사항, 산출물, 검증기준을 포함한다.
- 장문의 단일 프롬프트보다 기준 문서와 작은 작업 지시를 조합한다.
