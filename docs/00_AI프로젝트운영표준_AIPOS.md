# AI 프로젝트 운영 표준(AIPOS) v1.0

## 1. 목적

AIPOS는 사람과 AI가 함께 사업을 기획하고, 제품을 설계하며, 기술을 구현하고, 운영 안정성을 유지하기 위한 프로젝트 운영체계다.

이 표준은 다음 유형에 적용한다.

- AI 제품개발형: LAYAD와 같은 사용자 서비스
- AI 시스템 구축형: 데이터플랫폼, 업무시스템, AI 에이전트
- AI 전략·마스터플랜형: AI 데이터센터, 공공 데이터플랫폼, 중장기 구축전략

## 2. 핵심 철학

1. AI는 단독 의사결정자가 아니라 협업자다.
2. 설계가 개발보다 먼저다.
3. 대화는 기록이 아니며, 승인된 문서가 기준이다.
4. 사업자료·제품설계·기술자료를 분리한다.
5. 운영 중인 시스템은 차기 설계와 분리해 보호한다.
6. 모든 중요한 결정은 이유와 영향 범위를 남긴다.
7. AI 사용 비용과 효과를 함께 관리한다.
8. 결정된 사항만 기준 문서에 반영한다.
9. 개발·배포·운영 결과에 맞춰 문서를 지속적으로 현행화한다.

## 4. 2트랙 운영

### 트랙 A: 운영 안정화

- 현재 서비스와 데이터 보호
- 긴급 오류 수정
- 작은 변경 단위
- 배포 전 회귀 테스트
- 실패 시 복구 가능성 확보

### 트랙 B: 설계와 차기 버전

- 목표모델 설계
- 기술 검토
- 실험
- 문서화
- 컨설팅 자산화

트랙 B는 별도 브랜치에서 수행하고 검토·승인 후 필요한 항목만 트랙 A로 이관한다.

## 5. 표준 절차

1. 요구사항 접수
2. 현재 상태 확인
3. 기존 문서·코드·DB 영향분석
4. 목표 설계 반영
5. 요구사항 상태를 `DESIGNED`로 변경
6. 개발 승인 확인
7. 기능 브랜치 개발
8. 단위·통합·회귀 테스트
9. 배포 승인 확인
10. 배포
11. 실제 화면·데이터 검증
12. 관련 문서 현행화
13. 요구사항 상태와 변경이력 갱신

## 6. 상태 모델

- `IDEA`: 논의 중
- `DESIGNED`: 설계 확정, 미개발
- `DEVELOPED`: 코드 반영 완료, 배포 미확인
- `DEPLOYED`: 운영 환경 반영
- `VERIFIED`: 실제 사용자 경로와 데이터 검증 완료
- `DEFERRED`: 보류
- `REJECTED`: 폐기

상태가 없는 요구사항은 개발 대상으로 간주하지 않는다.

## 7. 문서 현행화와 변경관리

문서는 개발과 별개의 참고자료가 아니라 프로젝트의 공식 기준정보다.

### 반영 원칙

- 논의 중인 아이디어는 기준 문서에 확정사항처럼 기록하지 않는다.
- 사용자 또는 승인권자가 결정한 사항만 문서에 반영한다.
- 설계 확정 시 목표설계·요구사항·의사결정 문서를 갱신한다.
- 개발 완료 시 기술문서와 요구사항 상태를 갱신한다.
- 배포 완료 시 배포정보와 운영현황을 갱신한다.
- 실제 화면·데이터 검증 완료 시 현재 MVP 현황을 현행화한다.

### 변경이력 필수항목

- 변경일
- 변경 대상 문서
- 변경 내용
- 변경 이유
- 영향 범위
- 관련 요구사항 ID
- 관련 커밋 또는 배포정보
- 승인 및 검증 상태

문서와 운영 시스템이 불일치하면 운영 시스템을 임의로 문서에 맞추지 않는다. 먼저 실제 상태를 확인하고, 잘못된 쪽을 명확히 구분한 뒤 승인된 절차로 수정한다.

## 8. 의사결정 관리

모든 주요 결정은 다음을 포함한다.

- 결정일
- 결정 내용
- 결정 이유
- 검토한 대안
- 영향받는 화면·API·DB·운영절차
- 승인자
- 후속조치

## 9. AI 협업 원칙

- ChatGPT: 사업·제품·UX·문서 통합과 검토
- Codex: 코드 작성, 수정, 테스트, 리팩터링
- GitHub: 기준 문서, 코드, 변경이력의 단일 저장소
- Supabase 등 DB: 운영 데이터 저장
- Vercel 등 배포도구: 실행환경 관리

AI는 문서와 충돌하는 구현을 임의로 수행해서는 안 된다.

## 10. 품질 원칙

- 기능이 동작한다는 것과 운영 가능한 것은 구분한다.
- 모바일·PC·데이터·권한·오류처리를 함께 검증한다.
- 테스트 데이터는 식별하고 일괄 삭제할 수 있어야 한다.
- 비밀키와 개인정보를 코드·문서·화면에 노출하지 않는다.
- 배포 결과는 실제 운영주소에서 확인해야 완료로 인정한다.
- 배포 후 문서 현행화가 완료돼야 변경 절차가 종료된다.

## 11. 컨설팅 적용

AIPOS는 고객에게 특정 AI 도구를 판매하는 방법론이 아니다. 고객의 사업지식과 기술지식을 구조화하고, AI를 이용해 설계·개발·운영의 연결성을 높이는 방법론이다.

컨설팅 시에는 다음을 산출한다.

- 현황진단
- 사업목표와 KPI
- 목표모델
- 기술 아키텍처
- 단계별 로드맵
- 투자·운영계획
- AI 협업 및 지식관리체계
- 품질·보안·변경관리 기준
