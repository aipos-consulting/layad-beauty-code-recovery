# LAYAD Decision Log

## 2026-08-03 — 2트랙 운영 채택

결정:
- 운영 중인 MVP와 설계·기술문서화를 분리한다.
- 운영 안정화는 Track A, 문서·차기 설계는 Track B로 관리한다.

이유:
- 대화에 설계가 분산되어 반복 확인이 발생했다.
- 문서 정리 과정이 운영 코드를 불필요하게 변경해서는 안 된다.

영향:
- 문서 전용 브랜치를 사용한다.
- 명시적 승인 없이 Production 코드를 수정하지 않는다.

## 2026-08-03 — 제품 중심 재정의

결정:
- LAYAD의 중심을 단순 16유형 테스트에서 사용자 Beauty Code와 상품의 적합도 확인으로 명확히 한다.

핵심 문구:
> 선택하신 상품이 회원님의 Beauty Code와 얼마나 잘 맞는지 확인해 보세요.

영향:
- 사용자 상품 신청 및 결과 UI
- 관리자 최근 신청 목록
- 상품별 16유형 점수표
- 적합도 히트맵
- KPI와 분석 상태

## 2026-08-03 — MVP AI 운영 방식

결정:
- MVP에서는 OpenAI API 자동 분석을 기본 적용하지 않는다.
- 운영자가 ChatGPT Plus를 이용해 분석하고 검수 결과를 입력한다.

이유:
- 오너와 사전 합의되지 않은 API 비용 발생 방지
- 초기 품질 검수와 운영 학습 우선

## 2026-08-03 — 개인정보 최소화
