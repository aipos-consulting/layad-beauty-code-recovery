# LAYAD Target Design

## 1. 핵심 분석 방향

가장 중요한 분석은 다음 질문에 답하는 것이다.

> 사용자의 Beauty Code에 신청한 상품이 얼마나 잘 맞는가?

## 2. 사용자 상품 신청 결과

분석 완료 후 다음을 우선 표시한다.
- 회원님의 Beauty Code
- 신청 상품
- 해당 유형 적합도 점수
- 감성적 결과 문구
- 16유형 내 순위
- 최고 적합 유형과 점수 차이
- 축별 일치·불일치 설명
- 16유형 적합도 히트맵

대표 안내 문구:

> 선택하신 상품이 회원님의 Beauty Code와 얼마나 잘 맞는지 확인해 보세요.

## 3. 관리자 최근 상품 신청

각 신청 건에는 다음을 구분해 표시한다.
- 신청자 유형
- 신청 상품
- 신청자 유형에 대한 상품 적합도
- 적합도 등급
- 16유형 내 순위
- 분석 상태

`신청자 유형`, `상품 신청 유형 분포`, `상품 적합도 점수`를 혼용하지 않는다.

## 4. 상품별 16유형 점수분포

상품 하나당 16개 Beauty Code 점수가 존재해야 한다.

표시 방식:
- 4×4 히트맵
- 점수표
- 점수 높은 순/코드 순 정렬
- 신청자 유형 강조
- 최고점 유형 강조
- 미분석 유형 표시

등급 예시:
- 90~100: 매우 적합 / 매우 잘 맞아요
- 75~89: 적합 / 잘 맞아요
- 60~74: 보통 / 무난하게 맞아요
- 40~59: 낮음 / 일부 특성이 맞지 않을 수 있어요
- 0~39: 매우 낮음 / 다른 상품을 함께 비교해 보세요

## 5. 적합도 히트맵

### 단일 상품
16유형별 점수와 신청 건수를 4×4 셀로 표시한다.

### 여러 상품 비교
행은 상품, 열은 16유형으로 구성하여 특정 유형에 더 잘 맞는 상품을 비교한다.

### 최근 신청
최근 신청자의 Beauty Code에 해당하는 점수를 작은 히트맵 또는 강조 셀로 표시한다.

## 6. 통계 상세

- 연령대별 사용자 수
- 연령대별 상위 Beauty Code
- 국가별 사용자 수
- 대한민국 광역 지역별 사용자 수
- 지역별 상위 Beauty Code
- 지역 확인 불가 비율

원 IP는 저장하거나 표시하지 않는다.

## 7. 목표 DB 구조

`product_type_fits` 권장 필드:
- `product_id`
- `beauty_code`
- `fit_score`
- `fit_grade`
- `rank`
- `analysis_version`
- `analysis_summary`
- `evidence`
- `is_published`
- `created_at`
- `updated_at`

제약:
- `unique(product_id, beauty_code)`
- 점수 0~100
- 공개 전 16개 코드 존재 검증
